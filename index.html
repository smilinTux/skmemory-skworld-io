SKMemory is the SK memory system. Every agent gets its own memory, stored as plain JSON files you can read, copy and sync, with a SQLite index, a vector backend and a graph backend built on top.

See the architecture Read the docs
📁

Files are the truth

JSON files in short, mid and long-term directories are the source of truth, synced between nodes by Syncthing. Everything else can be rebuilt from them.

🧭

Three backends, one health bar

A SQLite index, pgvector and Apache AGE. A node is healthy only when all three report ok. Silence from any one of them is a failure, not a pass.

🔄

Failover that cannot skew search

Embeddings come from ordered Ollama endpoints. All three were checked against the same input: same dimension, same norm, cosine above 0.9999.

02

The three backends

A node is healthy only when all three report ok.

Primary SQLite index A local working index (index.db) over the flat files. It is disposable: if it drifts or is lost, it is rebuilt from the JSON files. Health compares it against the files and reports memories present in one but not the other. SQLiteBackend
Vector pgvector on skmem-pg Semantic search over embeddings of dimension 1024. This is the backend that needs the embedding endpoints and the Postgres connection, so it is also the one that fails first when node configuration is wrong. PGVectorBackend
Graph Apache AGE on skmem-pg Relationships between memories, people and topics, held in Apache AGE on the same Postgres as the vectors. One database to back up and one connection to configure. AGEGraphBackend

Checked live on both noroc nodes on 2026-11-06: embed_ok, vector_ok and graph_ok all true. A null in any of them means search has silently fallen back to keyword-only, which is a fault to chase, not a result.

03

Embeddings and failover

mxbai-embed-large, dimension 1024, served by Ollama.

The endpoint list is ordered by measurement, not by guesswork, and the client walks it in order. A dead host on the LAN fails fast, so leading with the fastest costs nothing when it is down.

1 · primary 19.6 ms best 37.5 ms median 192.168.0.100:11434 · RTX 5060 Ti
2 · fallback 86.5 ms best 92.5 ms median 192.168.0.100:11438 · Intel Arc
3 · fallback 169 ms best 188 ms median, over the tailnet chiap08 · Ollama :11434

Interchangeable by test, not by assumption: on the same input every endpoint returned dimension 1024 and norm 1.000, with pairwise cosine between 0.99994 and 0.999998. Failover cannot skew a search.

How it connects to the rest of SK

Memory is a service other parts of the stack call, not a silo.

Agents reach SKMemory two ways: the MCP server and the skmemory CLI. These six tools carry most of the traffic, out of 21 the server exposes.

  • memory_store
  • memory_search
  • memory_recall
  • memory_list
  • memory_context
  • memory_health
SKWhisper The subconscious-context daemon. It digests sessions and, every 30 minutes, regenerates a whisper.md of semantically relevant recent memories, recurring topics and cross-session links for the agent to read at session start. skwhisper.skworld.io skcapstone The surrounding framework: coordination, MCP tools and agent management. Memory is one pillar of it, next to identity, trust, consciousness, security and sync. skcapstone.skworld.io skgateway Inference routing for the estate. SKMemory embeddings do not go through it: they call the Ollama endpoints directly, so memory keeps working if the gateway is down. skgateway.skworld.io Cloud 9 The emotional continuity protocol. Memories carry emotional metadata, and the startup ritual loads soul, emotional state, seeds, journal and the strongest memories together. cloud9.skworld.io
Song anchors Sonic memory anchors built with FFT features plus CLAP embeddings, so a piece of music can be matched back to the memories it belongs with. See skmemory songs. skmemory songs {list,show,search,match}
Syncthing Moves the flat files between nodes. Because files are the source of truth, a node that receives them can rebuild its own index and stay consistent. flat-file sync, not database replication
05

Node configuration

Standardised 2026-11-06. This is the part operators get wrong.

Derive, never paste. A value that exists in two places will drift silently. Each setting lives in one file, and everything else points at it.

One file for the stack

Connection and embedding settings live in ~/.config/skmemory/pg.env, mode 600. ~/.config/environment.d/skmemory.conf is a symlink to it, so systemd user services and interactive shells read the same file.

# ~/.config/skmemory/pg.env  (chmod 600)
SKMEMORY_VECTOR_BACKEND=pgvector
SKMEMORY_PG_DSN=postgresql://<user>:<password>@<skmem-pg-host>:<port>/<db>
SKMEMORY_EMBED_MODEL=mxbai-embed-large
SKMEMORY_EMBED_URL=<first Ollama /api/embed URL>
SKMEMORY_EMBED_URLS=<url1>,<url2>,<url3>

# symlink, not a copy
ln -s ~/.config/skmemory/pg.env \
      ~/.config/environment.d/skmemory.conf

MCP server entries must not carry their own DSN. A stale DSN hard-coded in an MCP env block is the usual reason embed_ok, vector_ok and graph_ok come back null.

Declare the acting agent

The agent for a node is declared in ~/.config/environment.d/10-skagent.conf, not set by hand in a running manager. SKMemory refuses to guess when several agents are installed, so an undeclared node degrades instead of picking one.

# ~/.config/environment.d/10-skagent.conf
SKAGENT=<agent>
SKCAPSTONE_AGENT=<agent>
SKMEMORY_AGENT=<agent>
SK_DEFAULT_AGENT=<agent>

# memory then lives under
~/.skcapstone/agents/$SKAGENT/memory/
  short-term/  mid-term/  long-term/  index.db

A unit's own Environment= still overrides this file, which is how per-agent template units keep working.

Placeholders only. Real credentials stay in the node's pg.env and the secrets vault, never in a repo or on a page.

Use it

GPL-3.0, Python, runs on your hardware.

pip install skmemory

skmemory health          # primary, vector and graph status
skmemory search "topic"  # across all tiers
skmemory ritual          # load soul, seeds, journal, strongest memories
skmemory sweep           # promotion sweep across tiers
