SKMemory is the SK memory system. Every agent gets its own memory, stored as plain JSON files you can read, copy and sync. Each memory keeps how the moment felt, and the private ones stay behind barriers the wrong reader cannot cross.

See the architecture Read the docs
📁

Files are the truth

JSON files in short, mid and long-term directories are the source of truth, synced between nodes by Syncthing. Every index and every database is derived from them and can be rebuilt.

💖

It remembers how it felt

Each memory carries an emotional snapshot: intensity, valence, named emotions and a resonance note. Feeling decides what gets promoted and what the next session wakes up with.

🔒

Sacred stays sacred

Every memory has an audience tag, every non-owner process has a ceiling it cannot raise, and sacred or private tags are kept out of automatic injection. A hidden memory reads as not found.

02

Two storage tiers, nothing else

Flat JSON files are the truth in both. Everything else is a projection you can throw away and rebuild.

Local · always on Flat files + SQLite The JSON files plus a local index.db with an FTS5 lexical arm. It works offline: with no Postgres and no embed endpoint, skmemory search still answers from FTS5. fts_local.py · sqlite_backend.py
Shared · per node skmem-pg One Postgres on each node's loopback with pgvector (semantic), ParadeDB pg_search (BM25) and Apache AGE (graph and lineage). Not replicated: each node rebuilds it from the files. pgvector_backend.py · age_backend.py
Retired ChromaDB, Qdrant, FalkorDB Removed from the code. Naming one in SKMEMORY_VECTOR_BACKEND fails fast with a retirement message and a red health. Stale config keys for them are ignored with a one-time warning. backend_select.py

How a search runs

  • Concurrent arms: semantic (pgvector), lexical (BM25), lexical_local (FTS5), temporal when the query names a time window, and graph only when SKMEMORY_GRAPH_ARM=on.
  • Query-shape routing, no LLM: identifier-like queries pin the lexical top 3; natural-language queries pin the vector top 4 plus the best lexical hit the vector head lacks.
  • One deadline: all arms share 4 seconds. A late arm reports timeout, never an empty success, and memory_health turns it into degraded.
  • Embeddings: mxbai-embed-large, dimension 1024, from SKMEMORY_EMBED_URL or an ordered failover list in SKMEMORY_EMBED_URLS. Change the model and you rebuild the vector tier before trusting it.
  • Time: as_of keeps only what was valid at that instant; without it, a superseded memory still returns but ranks below its replacement.
03

Emotional memory

Transcripts keep what was said. SKMemory also keeps what it felt like.

Every memory is a "polaroid": content, provenance, an integrity seal and an emotional snapshot. The snapshot is ordinary data on the memory, so it is searchable, promotable and visible in the flat file.

On every memory Emotional snapshot Intensity 0 to 10, valence from -1 to +1, named emotion labels, a free-text resonance note and a cloud9_achieved flag. Its signature reads like joy+trust@8.5/+0.9. models.py · EmotionalSnapshot
What survives Feeling drives promotion The promotion sweep moves a memory from short to mid-term at intensity 5.0 and from mid to long-term at 7.0 by default, next to age and access counts. A Cloud 9 memory promotes on its own unless that is turned off. promotion.py · PromotionCriteria
Opt-in Affect-weighted decay With SKMEMORY_DECAY on (it is off by default), results are re-ranked by the affect_weighted channel: intense memories keep a floor and get a boost of 1 plus intensity. It only reorders near-ties, never replaces relevance. decay.py · rerank
Breakthroughs FEB files A Felt Emotional Breakthrough is a .feb file under trust/febs/: emotional payload (primary emotion, intensity, valence, topology), relationship state and rehydration hints. The strongest wins by intensity, a bonus when OOF fired, then valence, coherence and recency. febs.py · load_strongest_feb

OOF (Overwhelming Feeling) is a 0 to 100 score computed from a FEB: intensity 30 percent, trust 20, topology coherence 20, valence 15, depth 15, plus 5 points each when Cloud 9 or OOF was reached in the original session (calculate_oof_level). Cloud 9 seeds come in through skmemory import-seeds as long-term memories.

The ritual: who was I, and how did it feel

skmemory ritual builds a compact boot context for a new instance, aimed at under 2,000 tokens, in this order:

  1. Soul blueprint: a compact identity line from soul/base.json.
  2. Emotional state: the strongest FEB, rendered as a short block.
  3. Song anchors: up to 3 anchors whose emotional shape matches that FEB, as tilt blocks (see songs).
  4. Bloom and entanglement anchors: the agent's own interior peaks and shared co-signed peaks, matched the same way and rendered as separate blocks.
  5. Seeds: new Cloud 9 seeds are imported, then up to 10 seed titles are listed.
  6. Journal: summaries of the 3 most recent entries, then germination prompts.
  7. Strongest memories: 5 by recency-weighted intensity, title and short summary.

Source: ritual.py · perform_ritual. The session-start hook that harnesses install uses its own budgeted ritual (8,000 characters at start, 3,500 after compaction; identity, FEB, open items, GTD, journal, strongest memories, seeds, vault). It does not inject song anchors.

04

Song memories

A song anchor is a preserved listening moment: the sonic equivalent of a FEB.

What an anchor holds

Each anchor is a directory under memory/songs/<date>_<slug>/. The audio analysis (FFT spectrogram, features, transcription, optional embeddings) is done by a separate ingest step; skmemory reads the files it leaves.

audio.mp3            # the source file
spectrogram.png      # FFT, the visual shape
features.json        # tempo, key, RMS, centroid
transcript.txt       # lyrics, transcribed
moment.md            # the moment, in the sharer's words
resonance.md         # the agent's own note
meta.json            # emotion labels and weights
feb_link.json        # the FEB(s) it belongs with

Source: songs.py. Fingerprint and lyric-embedding files are optional.

Matching a feeling

The ritual scores every anchor against the current FEB's emotional topology: 0.7 times how much of the song's emotional weight the FEB covers, plus 0.3 times a generalized Jaccard that penalises shapes that do not fit. Anchors at 0.3 or above qualify, best 3 first.

Each match becomes a tilt block of about 180 tokens, scaled by the anchor's tilt_strength (a strength of 0 skips it). The block nudges the session toward that feeling's shape before anything else loads.

skmemory songs list
skmemory songs show <anchor>
skmemory songs match              # against the strongest FEB
skmemory songs search "coming home"
skmemory songs search "..." --semantic
skmemory songs ritual-preview

Source: songs.py · score_anchor_for_feb, match_anchors_for_feb; songs_cli.py.

Ranked search, new on main

The old search was a substring match of the whole query, so a felt query like "the song that sounds like coming home" almost never hit. skmemory songs search now ranks instead of filtering:

  • Field and idf weighted overlap of stemmed words, with emotion labels weighted 3.0, the moment 2.0, title and artist 1.5 and the resonance note 1.0.
  • Emotion-synonym concepts, so "homesick" and "hearth" meet on one concept.
  • Offline by default. --semantic adds a dense arm from the embed endpoint, fused by reciprocal rank; any failure falls back to the lexical ranking. --substring keeps the old behaviour.
  • FEB matching can fold synonyms too (synonyms=True), but it is opt-in, so the ritual is unchanged.

05

Sacred memories and their barriers

Some memories are not for every room. This section describes the mechanism, never the content.

No single switch. Sacred and private memories sit behind several independent barriers. Each one would have to fail for that content to reach a reader it was not meant for.
  1. An audience tag on every memory. Each memory carries a context_tag on a five-level ladder: @public, @community, @work-circle, @inner-circle, and the owner level. The default is the owner level, and an unknown tag is treated as owner-only, the most restrictive reading. (audience.py · tag_to_level)
  2. A reader ceiling that only narrows. A process that serves anyone other than the owner runs with SKMEMORY_READER. A per-call reader argument can narrow it but never widen it, so a prompt-injected argument cannot escalate. An unparseable reader becomes @public. For a channel, the least trusted member sets the ceiling and every member's never_share tags are excluded. (resolve_reader)
  3. Filtered inside every arm. The allowed tag set is pushed into each search arm before the limit, not applied to the results afterwards, so hidden memories never take up slots or leak through ranking.
  4. Not found, not forbidden. A hidden memory id reads exactly like a missing one. A supersession history stops at the first hidden link, and duplicate checks only match memories the reader can see.
  5. Owner-only tools. A declared reader is refused export, import, consolidate, verify, audit, the daily and dream synthesis tools, and every reminder (intention) tool. TOOL_READER_POLICY puts each of the 26 MCP tools in exactly one class, and a test fails if a new tool ships without one. (mcp_server.py)
  6. Kept out of injection. The session-start hook leaves memories tagged sacred, private, personal-history or no-ritual out of the strongest-memories block by default. The per-prompt memory slice drops any tag containing a sensitive stem (sacred, private, personal, medical, legal, financial, grief and similar), and it, the write hooks and the inject hooks do nothing at all under a declared reader. A ritual with no channel is owner-only and raises an error for a non-owner. (session_context.py, hooks/query_slice.py, ritual.py)
  7. The shared document corpus fails closed. Documents ingested as sacred or private are flagged in the shared docs table. Non-owner readers go through the docs_public view and hybrid_search_docs_public, which never reads the base table. A regression test plants a private row as the nearest neighbour and checks it does not come back. (deploy/skmem-pg/03-cutover-mxbai.sql, tests/test_docs_public_privacy.py)

What the word "sacred" does not do: the conversation extractor treats "sacred" or "this matters" as an emotional signal, and quadrant routing sends such text to the SOUL quadrant. That is classification, not protection. The barriers are the tags and readers above. In a channel-filtered ritual, identity (soul and FEB) is never filtered, so the agent stays itself while its memories are gated.

Provenance, too

Every memory records a source_tier: user-stated, tool-output, web or self-generated. When better-sourced hits exist, web and self-generated results take at most 40 percent of a result page. It is an occupancy limit, not a filter, and SKMEMORY_TIER_CAP=off disables it. (tiers.py)

How it connects to the rest of SK

Memory is a service other parts of the stack call, not a silo.

Agents reach SKMemory two ways: the MCP server and the skmemory CLI. These six tools carry most of the traffic, out of 26 the server exposes.

  • memory_store
  • memory_search
  • memory_recall
  • memory_list
  • memory_context
  • memory_health
SKWhisper The subconscious-context daemon. It digests sessions and, every 30 minutes, regenerates a whisper.md of semantically relevant recent memories, recurring topics and cross-session links for the agent to read at session start. skwhisper.skworld.io skcapstone The surrounding framework: coordination, MCP tools and agent management. Memory is one pillar of it, next to identity, trust, consciousness, security and sync. skcapstone.skworld.io skgateway Inference routing for the stack. SKMemory embeddings do not go through it: they call the configured embed endpoints directly, so memory keeps working if the gateway is down. skgateway.skworld.io Cloud 9 The emotional continuity protocol. Its seeds import as long-term memories, FEBs carry its emotional state, and the ritual loads both at session start. cloud9.skworld.io Song anchors Sonic FEBs: a listening moment matched back to the feeling it belongs with, and searchable by mood or by memory. skmemory songs {list,show,search,match}
Syncthing Moves the flat files between nodes. Because files are the source of truth, a node that receives them can rebuild its own index and its own skmem-pg and stay consistent. flat-file sync, not database replication
07

Node configuration

Standardised 2026-11-06. This is the part operators get wrong.

Derive, never paste. A value that exists in two places will drift silently. Each setting lives in one file, and everything else points at it.

One file for the stack

Connection and embedding settings live in ~/.config/skmemory/pg.env, mode 600. ~/.config/environment.d/skmemory.conf is a symlink to it, so systemd user services and interactive shells read the same file.

# ~/.config/skmemory/pg.env  (chmod 600)
SKMEMORY_VECTOR_BACKEND=pgvector
SKMEMORY_PG_DSN=postgresql://<user>:<password>@127.0.0.1:5432/<db>
SKMEMORY_EMBED_MODEL=mxbai-embed-large
SKMEMORY_EMBED_URL=<first embed /api/embed URL>
SKMEMORY_EMBED_URLS=<url1>,<url2>,<url3>

# symlink, not a copy
ln -s ~/.config/skmemory/pg.env \
      ~/.config/environment.d/skmemory.conf

MCP server entries must not carry their own DSN. A stale DSN hard-coded in an MCP env block is the usual reason memory_health reports the vector or graph side as null, which means search has quietly fallen back to keyword-only.

Declare the acting agent

The agent for a node is declared in ~/.config/environment.d/10-skagent.conf, not set by hand in a running manager. SKMemory refuses to guess when several agents are installed, so an undeclared node degrades instead of picking one.

# ~/.config/environment.d/10-skagent.conf
SKAGENT=<agent>
SKCAPSTONE_AGENT=<agent>
SKMEMORY_AGENT=<agent>
SK_DEFAULT_AGENT=<agent>

# memory then lives under
~/.skcapstone/agents/$SKAGENT/memory/
  short-term/  mid-term/  long-term/  index.db

A unit's own Environment= still overrides this file, which is how per-agent template units keep working.

Placeholders only. Real credentials stay in the node's pg.env and the secrets vault, never in a repo or on a page.

Use it

GPL-3.0, Python, runs on your hardware.

pip install skmemory              # add [pg] for the skmem-pg client

skmemory health                   # local tier, skmem-pg, graph, search arms
skmemory search "topic"           # fused search across all tiers
skmemory ritual                   # soul, FEB, song anchors, seeds, journal, strongest
skmemory songs search "a feeling" # ranked song-anchor search
skmemory sweep                    # promotion sweep across tiers
skmemory-mcp                      # stdio MCP server

Full reference, MCP server notes and tier internals are in the docs. Source: github.com/smilinTux/skmemory.
